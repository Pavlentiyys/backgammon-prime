# Техническое задание: Backgammon Prime (рабочее название)

> Веб-платформа для игры в длинные нарды с AI-коучем, мультиплеером и социальным слоем для рынка СНГ / Турции / MENA.

**Версия:** 1.0
**Статус:** MVP-спецификация
**Срок:** 7 дней

---

## 1. Резюме проекта

### 1.1. Описание
Веб-приложение для игры в **длинные нарды** (вариант, распространённый в СНГ, Турции, Иране, на Кавказе и в Центральной Азии) с поддержкой игры против бота, мультиплеера в реальном времени, асинхронных партий, AI-разбора сыгранных партий и социальных механик.

### 1.2. Бизнес-цели
- Занять нишу длинных нард, которая на международных платформах (Backgammon Galaxy, Play65, XG) представлена слабо или вообще отсутствует.
- Сформировать ядро возвращающейся аудитории через async-режим и городские лидерборды.
- Создать готовую к коммерциализации модель freemium (Pro-подписка + кастомные скины).

### 1.3. Целевая аудитория
- **Ядро:** мужчины и женщины 25–55 лет из СНГ, Турции, Закавказья, ЦА, где длинные нарды — часть культуры.
- **Вторичная:** молодёжь 18–25 лет, играющая в нарды с семьёй/друзьями и ищущая мобильный формат.
- **Третичная:** диаспоры в Европе и США.

### 1.4. Уникальное ценностное предложение
> «Backgammon Galaxy для длинных нард — с AI-коучем на родном языке и асинхронным режимом для работающих взрослых».

### 1.5. Прямые конкуренты и отстройка
| Конкурент | Что у них | Что у нас лучше |
|---|---|---|
| Backgammon Galaxy | Короткие нарды, премиум-AI | Длинные нарды, локальная аудитория, async |
| Play65 / Backgammon.com | Старый UX, нет AI-разбора | Современный UX, Claude-коуч |
| Lichess-style (открытые) | Нет под нарды | Заполняем пустоту |
| Мобильные игры (Tabla и т.п.) | Слабый мультиплеер, реклама | Web-first, чистый интерфейс, ELO |

## 2. Глоссарий

| Термин | Определение |
|---|---|
| Длинные нарды | Вариант нард, где обе стороны начинают с 15 фишек в одном углу доски и движутся в одном направлении против часовой стрелки. |
| Пункт (point) | Одна из 24 позиций на доске. |
| Дом (home board) | Последние 6 пунктов перед снятием фишек (пункты 19–24 для каждого игрока относительно его направления). |
| Голова | Стартовый пункт, где находятся все 15 фишек в начале партии. |
| Бросок (roll) | Результат броска двух кубиков. |
| Дубль | Бросок одинаковых значений (1-1, 2-2 и т.д.) — играется 4 раза. |
| Блок (block) | Любой пункт, занятый одной или более фишек соперника, на который нельзя поставить свою фишку. |
| Прайм | Цепочка из последовательных занятых пунктов. |
| Марс | Победа, когда соперник не успел снять ни одной фишки (×2 очка). |
| Кокс (хоум-марс) | Победа, когда соперник не вывел ни одной фишки в свой дом (×3 очка). |
| Pip count | Сумма ходов, нужных игроку для вывода всех фишек. Базовая метрика преимущества. |

## 3. Функциональные требования

### 3.1. Игровое ядро (Engine)
**Описание:** чистый TypeScript-модуль без зависимостей от UI/сети. Pure functions.

**Должен реализовать:**
- `createInitialState(): GameState` — начальная позиция длинных нард.
- `rollDice(rng): [d1, d2]` — бросок с использованием детерминированного RNG (для replay).
- `getLegalMoves(state, dice): Move[]` — список всех легальных последовательностей ходов.
- `applyMove(state, move): GameState` — применение хода, возвращает новое состояние.
- `isGameOver(state): { over: boolean, winner?, type?: 'normal'|'mars'|'koks' }`
- `pipCount(state, color): number`
- Сериализация / десериализация в JSON.

**Особые правила длинных нард (см. раздел 4) реализуются здесь и только здесь.**

**Критерии приёмки:**
- Покрытие unit-тестами ≥ 80% для функций правил.
- Тесты на edge-cases: правило головы, запрет полного блока, дубль на первом ходу, оба кубика непригодны.

### 3.2. Hot-seat (игра вдвоём на одном экране)
- Два игрока ходят по очереди на одном устройстве.
- Бросок кубиков нажатием на доску.
- Подсветка легальных пунктов после броска.
- Drag-and-drop фишек + tap-to-move (для мобильных).
- Undo последнего полу-хода до завершения хода (нажатие «Готово»).
- Определение победителя с указанием типа победы (обычная / марс / кокс).

### 3.3. Игра против бота
- Три уровня сложности: Лёгкий / Средний / Сложный.
- Алгоритм: **expectimax глубины 1 / 2 / 3** соответственно.
- Эвристики оценки позиции: pip count, контроль ключевых пунктов, длина праймов, бэк-чекеры в зоне риска, потенциал блока.
- На лёгком уровне — добавление шума к оценке для имитации человеческих ошибок.
- Время на ход бота: ≤ 1.5 секунды на любом уровне.
- Возможность сдачи партии.

### 3.4. Мультиплеер real-time
- **Создание комнаты по ссылке без обязательной регистрации** для гостя.
- Хозяин комнаты создаёт игру → получает короткую ссылку (`/play/abc123`) → отправляет другу.
- Поддержка приватных и публичных комнат.
- Matchmaking для публичных комнат по ELO (±150 пунктов).
- Состояние игры реплицируется через Supabase Realtime / WebSocket.
- **Серверная валидация всех ходов** — клиент не имеет права записывать в БД напрямую.
- Таймер на ход: 30 / 60 / 120 секунд (выбирается при создании комнаты).
- При дисконнекте — 60 секунд на возврат, иначе техническое поражение.
- Спектатор-режим для публичных партий (read-only подписка).

### 3.5. Async-режим (correspondence)
- Игроки ходят, когда удобно, таймер 24 часа на ход.
- Один игрок может вести параллельно до 10 async-партий (Pro — без лимита).
- Push-уведомления о ходе соперника (web push через service worker).
- Email-уведомления как fallback.
- Отдельная вкладка «Мои партии» с индикаторами «ваш ход / ход соперника».

### 3.6. AI-коуч (анализ партии)
**Описание:** после завершения партии (или по запросу) система анализирует ходы игрока и выдаёт текстовый разбор.

**Алгоритм:**
1. Для каждого хода игрока движок считает best move (expectimax depth 3) и pip-эквивалент потери (equity loss).
2. Ходы классифицируются: 🟢 Excellent (loss < 0.5), 🟡 OK (0.5–2), 🟠 Mistake (2–5), 🔴 Blunder (> 5).
3. Топ-3 самых значимых ошибки отправляются в Claude API с контекстом позиции (FEN-подобная нотация).
4. Claude возвращает объяснение на родном языке игрока: что было сыграно, что было сильнее, почему.

**UI разбора:**
- График точности игрока по ходам партии.
- Список ходов с подсветкой ошибок.
- Возможность кликнуть на ход → увидеть позицию и комментарий ИИ.
- Сводный итог: «Accuracy: 87%, 2 серьёзные ошибки в эндшпиле».

**Лимиты:**
- Бесплатно: 3 разбора в месяц.
- Pro: без лимита.

## 4. Правила длинных нард (точная спецификация)

Этот раздел — авторитетный источник для разработки игрового ядра.

### 4.1. Начальная расстановка
- Доска: 24 пункта, пронумерованы 1–24 для каждого игрока относительно его направления движения.
- В начале партии **все 15 фишек каждого игрока стоят на пункте 24** (своей «голове»).
- У белых и чёрных головы находятся в противоположных углах.

### 4.2. Направление движения
- Оба игрока движут свои фишки **против часовой стрелки**.
- Каждый игрок проходит свой путь от пункта 24 до пункта 1, после чего начинает снимать фишки с пункта 6 и ниже (своего дома).

### 4.3. Первый ход
- Каждый игрок бросает один кубик; чей больше — ходит первым своим броском обоих кубиков.
- При равенстве — перебрасывают.

### 4.4. Бросок и ход
- Игрок бросает два кубика.
- Значения кубиков играются отдельно: можно одной фишкой на сумму, можно двумя разными фишками.
- **Дубль** (одинаковые значения) играется 4 раза.
- Если ни один из ходов нельзя сделать — ход переходит сопернику (полностью или частично пропускается).
- Если можно сыграть только один кубик — игрок обязан сыграть тот, что позволяет это сделать (предпочтительно бóльший, по стандартным правилам).

### 4.5. Правило головы
- **С головы (пункт 24) за один ход можно снять только одну фишку**, кроме первого хода, где при бросках 6-6, 4-4 и 3-3 разрешается снять две фишки.

### 4.6. Запрет на занятый соперником пункт
- Нельзя поставить фишку на пункт, где стоит **хотя бы одна** фишка соперника.
- В длинных нардах **фишки не «бьются»** (в отличие от коротких) — пункт занят даже одной фишкой.

### 4.7. Запрет «полного блока»
- **Игрок не имеет права построить непрерывный прайм из 6 пунктов, если впереди этого прайма нет ни одной фишки соперника.**
- То есть нельзя «запереть» все фишки соперника так, чтобы он не мог двинуться. Прайм длиной 6 допустим только если хотя бы одна фишка соперника находится впереди прайма.

### 4.8. Дом и снятие
- Когда все 15 фишек игрока находятся в его доме (пункты 1–6), он может начать снимать фишки.
- Снятие производится бросками: бросок N снимает фишку с пункта N.
- Если на пункте N фишек нет, можно снять с более высокого пункта (только если в доме нет фишек выше N).
- Если бросок больше любого занятого пункта — снимается фишка с самого высокого занятого.
- Во время снятия можно по желанию двигать фишки внутри дома вместо снятия.

### 4.9. Победа
- Игрок, первым снявший все 15 фишек, побеждает.
- **Обычная победа:** соперник успел снять хотя бы одну фишку → 1 очко.
- **Марс (mars):** соперник не снял ни одной фишки → 2 очка.
- **Кокс (хоум-марс):** соперник не снял ни одной и не успел все ввести в свой дом → 3 очка.

### 4.10. Изменение состояния ELO
- Победа: +K * (1 - expected), где K = 32, expected по стандартной формуле ELO.
- Марс: множитель ×1.5, кокс: ×2 к разнице ELO.
- Сдача = поражение без модификатора.

## 5. Нефункциональные требования

### 5.1. Производительность
- LCP < 2.5 с на 4G.
- Время реакции на ход (клик → визуальный отклик): < 100 мс.
- Размер JS-бандла главной страницы: < 250 KB gzipped.
- Серверная валидация хода: < 50 мс p95.

### 5.2. Адаптивность
- Mobile-first дизайн (минимальная ширина 360 px).
- Тестовые брейкпоинты: 360, 768, 1024, 1440.
- Touch-управление (drag + tap-to-move) полностью эквивалентно мышиному.
- Поддержка landscape на мобильных.

### 5.3. Безопасность и анти-чит
- Серверная валидация всех ходов в мультиплеере и async.
- RNG бросков — на сервере, клиент только отображает.
- Rate limiting на API (например, 100 запросов/мин на пользователя).
- Логи всех ходов для возможности расследования.
- Защита от автоматизированной игры: подозрительные паттерны (нечеловеческая точность, слишком быстрые ходы) флагируются для ручного ревью.

### 5.4. Доступность
- Контраст ≥ WCAG AA.
- Keyboard navigation для основных действий.
- ARIA-метки на интерактивных элементах.

### 5.5. SEO
- SSR для landing, страниц лидерборда, публичных профилей, страниц партий.
- Open Graph мета-теги.
- Sitemap.xml.

## 7. Архитектура

### 7.1. Высокоуровневая схема
```
[Next.js client] ←→ [Supabase API + Realtime] ←→ [Postgres]
       ↓
[Edge Functions: move validation, ELO, AI-coach call]
       ↓
[Anthropic API] + [Stripe API]
```

### 7.2. Структура БД (Supabase / Postgres)

**`profiles`** — публичный профиль игрока (расширение `auth.users`).
- `id` (uuid, FK auth.users), `username`, `avatar_url`, `city`, `country`, `elo` (int, default 1200), `created_at`, `is_pro` (bool), `pro_expires_at`.

**`games`** — каждая партия.
- `id` (uuid), `type` ('bot' | 'realtime' | 'async' | 'hotseat'), `player_white`, `player_black`, `status` ('waiting' | 'active' | 'finished' | 'abandoned'), `winner_color`, `win_type` ('normal' | 'mars' | 'koks'), `state` (jsonb — текущее состояние доски), `created_at`, `finished_at`, `time_per_move` (int, секунды), `last_move_at`.

**`moves`** — лог ходов (для replay и анализа).
- `id`, `game_id` (FK), `move_number`, `player_color`, `dice` (int[]), `move` (jsonb), `state_after` (jsonb), `created_at`.

**`rooms`** — комнаты для приглашений по ссылке.
- `id`, `slug` (короткий код), `game_id`, `host_id`, `is_public`, `created_at`, `expires_at`.

**`analysis`** — кэш AI-разборов.
- `id`, `game_id`, `user_id`, `accuracy`, `mistakes_count`, `blunders_count`, `summary_text`, `move_comments` (jsonb), `created_at`.

**`leaderboard_weekly`** — материализованное представление для быстрой выдачи топов, обновляется кроном раз в час.

**RLS-политики:**
- Игрок может читать только свои `profiles` (кроме публичных полей) и партии, в которых участвует.
- Запись в `moves` — только через Edge Function (валидация).

### 7.3. API (Edge Functions / Route Handlers)
- `POST /api/game/create` — создать игру (бот / комната).
- `POST /api/game/:id/move` — отправить ход (с валидацией движком).
- `POST /api/game/:id/resign` — сдаться.
- `GET /api/game/:id` — состояние партии (для гостей).
- `POST /api/analysis/:gameId` — запросить AI-разбор.
- `GET /api/leaderboard?scope=global|city|country` — топы.
- `POST /api/stripe/webhook` — апдейт статуса Pro.

### 7.4. Real-time протокол
- Каждая `games` строка подписывается обоими игроками + спектаторами через Supabase channel `game:{id}`.
- Изменения в `state` и `moves` автоматически реплицируются.
- Презенс (онлайн / печатает / бросает) — через Supabase Presence.

### 7.5. Игровой движок
- Расположение: `/lib/engine/` (изоморфно работает на клиенте и в Edge Function).
- Без зависимостей кроме стандартной библиотеки.
- Сериализация состояния — компактная (~ 200 байт JSON).

## 12. Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| Не успеть мультиплеер за день | Средняя | Использовать Supabase Realtime (не своё WS), упростить до 1 типа комнат |
| Бот играет слишком слабо/медленно | Средняя | Заранее заложить expectimax с глубиной как параметр; кэшировать оценки |
| AI-разбор галлюцинирует | Средняя | Подавать в Claude конкретные числа (equity loss, pip count), а не «угадай хорошо ли» |
| Незаполненные лидерборды → не вирально | Высокая | Seed-данные: 50 фейковых аккаунтов с реалистичными ELO на демо |
| Stripe требует верификации бизнеса | Высокая | Только test mode на MVP, реальная интеграция — после демо |
